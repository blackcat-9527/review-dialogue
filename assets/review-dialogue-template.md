# Shared Review Dialogue

## Artifacts and roles

- Shared log: Enter the supplied path, or automatically create a reviewer-owned log in the current workspace as `<artifact-stem>_Review_Dialogue.md` or `Review_Dialogue.md`. Reuse a matching existing log; never overwrite an unrelated log.
- Original artifact: Enter its actual absolute path.
- Latest artifact and status: Later appended registrations take precedence.
- Author: Identify the chat's role and actual environment identity.
- Reviewer: Identify the chat's role and actual environment identity.
- Scope: Record the requested review scope and whether this is a sample or template.

## Working agreement

Both participants exercise independent judgment. The author may accept, partially accept, or reject comments; another agent's feedback is not authoritative. Use actual passages and directly relevant sources, disclose unavailable originals and other verification limitations, and do not invent data.

For either "Continue review" or "繼續審閱", first reread the latest log entries and designated artifact, then resume this chat's established role. Append responses only. Reread the end immediately before writing and reassess if it has changed. Preserve originals and earlier versions; create a new numbered version only when content changes.

The author makes supported revisions and validates them; the reviewer checks them before closing issues. Close when no new substantive problem remains, without manufacturing revisions to prolong the exchange. The log does not automatically notify or wake another chat.

## Dialogue

Use the format below for each round, replacing the instructions with actual information when writing the first entry.

### Round N | Role and identity | Date and time

- Read: Absolute artifact path and the latest entry read; include a hash when useful.
- Item-by-item response: R1 or other identifiers, decision, actual passage, evidence, and revision or rebuttal reasons.
- Output: Absolute path to the new artifact, or explain that no artifact changed.
- Validation: Checks actually performed, evidence levels, and limitations.
- Handoff: What the next participant should handle, or confirmation that all scoped issues are closed.
